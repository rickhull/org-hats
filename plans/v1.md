# org-hats v1 — what remains

**Status:** `1.2.0` is released on `main`, and the consumer's pin,
parser swap, and re-recorded acceptance are complete. Since the release,
`main` has gained, additively: the duplicate-link bootstrap hardening,
real-world scenario tests with the Berlin Airlift twin, and the Cloudflare
runtime's provider-callback exchange and production Worker config. What
remains is the consumer's deployment and the decisions still open; the
v0.4 line is frozen at its tags, and history is in commit messages.

## C1 — Consumer adoption

- [ ] **Quartermaster adopts the runtime and retires the stand-ins.** The
  `v1.2.0` pin, the `verificationKeysFrom` swap, the re-recorded
  acceptance, and the authority-free browser login flow are complete on
  their side (relay, 2026-10-24/25); the 1.1 `Organization` field rename
  rode along with the pin move. What remains is theirs: deploy the
  Cloudflare runtime — pinning the Cloudflare revision independently of
  the portable tag — swap the `AUTHORITY` service binding, run
  conformance across the binding before any product login, and delete
  `apps/authority-dev` plus `packages/access` together.

## Decided

- [x] **The Cloudflare tag scheme is `cloudflare-vX.Y.Z`**, distinct from
  the root `vX.Y.Z`; `bin/check-version` matches only `v<semver>` tags, so
  the prefix never collides. The first tag, `cloudflare-v0.1.0`, matches
  the package's own `0.1.0` and lands with the commit that adds the
  production Worker config and the provider-callback exchange — the
  revision Quartermaster's `reporting-stream-authority` deployment pins.

- [x] **The provider-callback exchange landed as Cloudflare runtime
  surface** (`evidenceFromProviderCode` on the entrypoint): explicit
  input from the callback, evidence-only result, the tenant-supplied nonce
  verified by the runtime, and discovery, the token POST, and JWKS (with
  rotation refetch) behind the seam with the client secret. The portable
  seam stays evidence-only; the consumer's `v1.2.0` pin does not move.

## Open decisions

- Production access lifetime and fresh-auth policy: the consumer's
  security review owns the number; the engine defaults to 900 seconds.
- A read-only hat is not expressible in v1: `validatePolicyBundle` rejects
  a role with zero actions, so an auditor (read reach, no act capability)
  has no natural carrier. It arrives with the team-audience axis —
  Quartermaster's `read_audience` requirement — not by weakening the
  bundle validation ahead of the consumer that needs it.
